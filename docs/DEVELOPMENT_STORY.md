# 我如何继续开发 Super Lib

**简体中文** | [English](DEVELOPMENT_STORY.en.md)

作者：[aimtowin](https://github.com/aimtowin) · 记录至 2026-11-18（[Super Lib 2.5.0](https://github.com/aimtowin/Super/releases/tag/v2.5.0)）

我从现有的开源素材管理器起步。2026 年 8 月，我建立了 Super 的独立仓库、发行序列和 `.super` 资源库标识。但后来决定这个项目走向的，不是名字和图标，而是我在素材库里反复遇到的问题：切文件夹时应该先看到什么？磁盘扫描能不能让出操作时间？改一处功能，用户为什么还要下载整个安装包？这篇记录写的是我怎样把这些问题变成了可查的实现和发行。

## 先让人看到素材，再补齐后台工作

早期开发中，我把首屏分页从“所有资产”扩展到目录浏览，并将侧栏统计、精确计数和媒体派生任务从首屏路径拆开。这一阶段的多轮迭代由 [2.2.8 源码基线](https://github.com/aimtowin/Super/commit/6ad35fe55b24bdb2cc48b9e53543af07e6e17c67)收束，并非每个中间版本都有独立提交。

真正棘手的是并发：快速换目录时，旧请求返回不能覆盖新画布；后台 AI 或磁盘变化触发刷新，也不能顺手打断全屏预览、筛选或正在编辑的描述。到 [2.3.17](releases/v2.3.17.md)，我把分页结果绑定到浏览会话和查询代次，合并重复刷新，并让当前资产的详情读取优先于多选批量读取。[2.3.21](releases/v2.3.21.md) 再把右侧统计和封面查询移出首屏路径，明确区分“还在加载”“真的空”和“读取失败”。[2.4.4](releases/v2.4.4.md) 则把手动刷新改成可取消、可让出执行时间、同一资源库不重复启动的任务，避免一次全量磁盘扫描占住整个资源库进程。

这些改动也有局部测量。[2.4.2 的热缓存启动 A/B](releases/v2.4.2.md) 中，窗口出现时间从 **2336.5 ms 降到 662.5 ms**，资源库可用时间从 **2787.5 ms 降到 2254 ms**（生产型测试，`n=2`）；同版的 **50,000 条目布局函数基准**中，100 个分页块的累计计算时间从 **804.0 ms 降到 403.5 ms**。这是 Super Lib 自身前后版本在指定条件下的结果，不是整机速度或真实 NAS 表现的承诺。

浏览更快也不能靠省略数据检查。我把「从库中解除引用」和「从磁盘删除」明确分开：解除链接默认保留外部原文件；同步区分暂时缺失和用户明确删除，断连或离线不会被传播为删除指令。这些规则随 [2.3.18](releases/v2.3.18-validation.md) 交付，[阶段验收](reference/followup-phase1-results-2026-10-09.md)记录了本地库和模拟远端的回归范围，没有把它当成真实 NAS 或 WebDAV 多写者验收。

## 把 Windows 更新做成可验证的交付流程

我逐步建立了 Windows 安装器、文件级增量、版本清单、哈希校验和构建溯源。客户端匹配精确的来源版本：有对应增量就用，没有匹配或增量校验失败就回退完整包。发行时会记录构建输入和产物，避免把旧安装器或过期增量混进新版本。

[2.4.1 的发行验收](releases/v2.4.1-validation.md)记录了一个实际例子：从 2.4.0 到 2.4.1 的增量包是 **2,031,262 字节**，约为完整包的 **1.0%**。我也在 2.4.0 安装版上完成了发现更新、下载、安装和自动启动的实机流程；当次没有另取客户端日志，不能据此断言实跑使用的就是该增量包。这是特定版本对的交付记录，不是以后每次更新都会达到的体积比例。

## 让素材工具按需长出来

我保留本地素材管理免费、免账号的原则，并把可选工具做成独立拓展。[2.4.6](releases/v2.4.6.md) 建立 Super Lib 自己的拓展目录：安装包须来自指定 HTTPS 源，并核验大小和 SHA-256。首个通过此目录交付的拓展是**无限画布**：它能打开多个独立参考小窗，主窗口保持可见；默认悬浮预览仍保留原有操作。

[2.4.8](releases/v2.4.8.md) 交付了**图片素材生成工作台**，把生成、预览、原图下载和历史放进素材工作区，同时把上游凭据留在服务端。[2.4.9](releases/v2.4.9.md) 加入原生与超分渠道，并把拓展更新从应用发版中拆开：打开「设置 → 拓展」时检查版本，在宿主兼容的前提下可独立更新，并保留原有启用状态。[2.5.0](releases/v2.5.0.md) 继续修复了启动更新提示的时序问题，并把图片下发改成服务器接收后、客户端流式下载并显示真实字节数和百分比的进度页。这是可选的联网能力，不是使用本地素材库的前提。
