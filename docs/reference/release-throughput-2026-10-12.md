| 阶段 | 观测耗时 | 结论 |

测试也占明显时间：原主线约 20.8 分钟，另一次完整 GUI 复测约 10.3 分钟。复测针对首次运行中的 Playwright worker 提前退出，不能删掉测试门禁或直接把框架失败记成应用失败。本轮不调整测试范围。

调用链复核：

1. `build-retained-deltas.mjs` 为每个来源顺序调用实际增量生产者，完成后再次验证该增量的来源。
2. `build-inno-delta.mjs` 在开始、编译后和派生物来源绑定时验证程序包。
3. `artifact-manifest.mjs` 的绑定前后及读取派生物来源时调用完整程序验证。
4. `build-provenance.mjs` 每次验证重新枚举并校验所有程序文件，同时校验不可变源输入和固定媒体。

每个增量至少触发五次完整程序检查。这不是五次编译，但重复的全目录串行读取、路径检查和 SHA-256 计算使单次约 11 秒的成本被放大。**没有把 25.6 分钟全部宣称为哈希，也没有把逻辑读取字节数当作真实磁盘 I/O 量。**

## 改了什么、没有改什么

- `bounded-map.mjs` 限制在途读取、保持结果顺序。首个失败后停止派发新任务，等待所有正在读取的任务收尾，然后抛出原错误，不遗留打开的文件流或未处理的 Promise 失败。
- 输入捕获和程序普通文件哈希改为四路有界读取；目录枚举、文件身份、读取前后属性检查、完整字节 SHA-256 与 macOS 链接最终复核仍保留。
- 不以版本号、文件长度、mtime 或前一次结果缓存代替真实读取。不减少完整程序验证调用次数。
- 增量构建增加 `build-retained-deltas:timing` JSON 日志，分别记录实际子进程耗时与父进程的派生物验证耗时，避免以后靠模型等待时间判断脚本性能。
- 保留 20 个来源增量覆盖、现有安全门禁、版本与凭据格式；没有改应用浏览、导入、数据库或更新服务协议。
- 完整新版本发布流程尚未重新运行，**不能据单函数提速保证整个发布耗时缩短 64%**。上传及公网下载仍取决于真实网络；没有操作 ECS 配置。

旧 2.3.21 构建凭据、基线及发行附件未改写。当前生产脚本已经变化，旧凭据正确报出 `Immutable input drift/changed`，拒绝将新源码伪装成旧构建。下一次发布应从新源码生成新的完整构建证明，不能修改旧证明来让验证通过。
