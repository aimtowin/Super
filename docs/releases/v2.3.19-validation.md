标签双击失败的初步排查先消除了无预览时不必要的异步等待；宽窗口连续 5 次通过，但这不能证明根因已关闭。补充「无预览立即提交导航」「有预览等待并保留会话失效保护」测试。新增状态读取要求测试函数边界显式注入 `previewAsset`，先前缺口导致的失败已记录，不通过删除断言掩盖。

初次直接用宿主 Node 执行 Worker 测试遇到 Electron/Node 原生 SQLite ABI 不同；改用项目既有 Electron Node 测试入口后上述 33 项全部通过，未修改或放宽生产 ABI 校验。

第二次完整窗口运行：92 通过／11 条件跳过／2 失败。PDF 点击关闭后进程先销毁窗口导致测试点击回执报已关闭，改为等待实际 close 事件，并仅接受窗口确已关闭的点击异常；连续 5 次真实窗口通过。标签失败仍出现，继续审查发现管理控件误进入资产框选，小于 5 像素的点击还残留 `is-marquee-active`；隔离标签／插件视图和交互控件，提前清理样式。真实 hook 和导航边界 37 项通过，完整门禁重跑，不将先前 5 次或带诊断监听的 10 次通过代替全量验收。

## 窄窗口根因复现与收尾

隔离副屏 1080×900 窗口连续两次复现：第一次点击让条件显示的选择计数在工具栏换行，标签纵向位移；第二次点击实际落在工具栏，页面始终有焦点。修复为始终挂载、固定高度的独立状态区，未选择时显示双击提示。真实窗口断言选择前后标签坐标不变；副屏连续 3 次完整标签流程通过，状态区组件测试 2 项通过。

第三轮全量窗口另有缩略图解码、合集新建和删除时序失败；当时额外 GUI 实验并发污染了部分窗口验证，重新串行运行完整门禁，不把定向通过当作全量通过。删除测试改为等待真实 Worker 回收站变更完成再断言，缩略图失败保留图片状态与会话日志，未降低生产校验。第二轮合同门禁实际 4935 通过／25 跳过；本次布局修改后再跑完整合同及窗口门禁。

串行完整窗口运行又暴露文件夹标题回归测试的错误前提：预览图片正常由缩略图升级到原图，测试却要求临时缩略图 URL 永久不变。改为等待实际原图解码，再保留原有 URL、节点连接、资产、焦点与路径断言；未关闭渐进加载或放宽生产逻辑。该轮结束后重新完整验收。

后续媒体格式验收在批量导入选择尚未稳定时点击单项，实际打开默认批量焦点 `clip.flv` 而非 `sample.jfif`；不是 JFIF 解码失败。测试先等待批量揭示结束、用既有 Escape 清除批量选择，再断言单项选中及各格式真实解码。本测试不覆盖导入尚未结束时抢先改选的交互。另一项快速开始测试遭遇 Playwright 测试进程异常退出（Windows 3221226505），保留失败记录并专项复跑，不将其写成通过或未经核实归因于应用。

媒体格式和快速开始组合连续 3 轮（9 项）通过。四角菜单测试还在导入定位未稳定时于数十毫秒内依次打开菜单，受后续定位滚动的菜单关闭条件影响；同样先完成导入并取消待执行的揭示选择，再检查全部四角边界。没有删除边界断言，也没有关闭菜单的滚动／失焦保护。

进一步保留的缩略图诊断显示所有图片已解码，失败的是单项检查器因延迟批量揭示而被切换；据此补充生产修复：主动资产选择／资产菜单取消已有待执行的揭示与焦点 token。真实 Hook 计时器回归确认超过 280ms 后仍保持用户的单项选择与无待执行焦点，相关 6 项单元测试通过。三个相关真实窗口测试撤去 Escape 前置规避，直接验证主动点击／右键能取消待执行动作；默认导入定位、后台选择保护与菜单关闭条件均保留。尚未完成的导入期间改选仍不在此项承诺范围。
