# 悬浮图片预览窗口

## 目标

让已打开的静态图片预览可切换为独立、无框、始终置顶的浮窗。触发后主窗口最小化；关闭浮窗后恢复主窗口和原来的查看上下文。

## 方案取舍

1. **独立 `BrowserWindow`（采用）**：满足主窗口最小化、跨应用置顶、原生拖动/缩放和独立生命周期。
2. 主窗口内的 DOM 浮层：不能在主窗口最小化后持续显示，也无法可靠置顶到其他应用之上。
3. 调用系统图片查看器：会失去 Super 的样式、受控关闭恢复和资源安全边界。

## 安全与状态边界

- 主渲染器只提交 `libraryId`、`assetId`；不提交文件路径或图片 URL。
- 主进程重新通过 Worker 解析预览，确认是 `ready` 的 `image` 后才创建浮窗。
- 浮窗使用专用 preload，只可读取 Main 保存的当前只读预览状态，以及请求关闭自身；没有完整库 API、Node API 或导航能力。
- 同一时间仅维护一个浮窗；关闭/崩溃时清理状态并恢复仍存活的主窗口。

## 交互

- 图片调节栏右侧出现“悬浮预览”按钮；仅在可用静态图片预览上展示。
- 浮窗默认 960×640、无系统边框、可调整大小、`alwaysOnTop` 使用 Electron 的 `screen-saver` 级别。
- 顶部隐约的拖动带可移动窗口；右上角关闭和 `Esc` 关闭；图片始终 `object-fit: contain`。
- 关闭浮窗会恢复并聚焦主窗口，原图片查看器不卸载。

## 验证

- 协议单元测试：仅接受语义化 ID，请求/响应不含路径。
- Electron E2E：打开图片 → 点击悬浮 → 出现第二窗口且图片解码 → 主窗口最小化 → 关闭浮窗后主窗口恢复。
- TypeScript、ESLint、目标 E2E，以及一次开发版人工检查。
