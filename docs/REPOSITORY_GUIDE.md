# Super Lib 仓库地图

本仓库是 Super Lib 的 Windows-first Electron 桌面应用。代码、可复现构建
输入和本地可重建产物必须分开管理；不要把 `out/`、`tmp/` 或开发用户数据
提交到 Git。

## 代码层次

| 路径 | 职责 |
| --- | --- |
| `src/main/` | Electron 主进程：窗口、托盘、自动更新、原生文件操作与 Worker 生命周期。 |
| `src/preload/` | 主进程与渲染进程之间的受限 IPC 桥。 |
| `src/renderer/` | React 界面：资产浏览、设置、主题、预览、筛选和交互。 |
| `src/worker/` | 本地资料库数据库、索引、缩略图、文件监听、导入和 AI 任务。 |
| `src/shared/` | IPC 协议、请求/响应类型、跨进程工具函数。 |
| `extension/` | 浏览器扩展和扩展运行时相关资源。 |

依赖方向是 `renderer -> preload -> main -> worker`；跨层数据类型优先放在
`src/shared/`，不要让渲染层直接读取 Node 或数据库实现。

## 构建、发布与资源

| 路径 | 职责 |
| --- | --- |
| `scripts/` | 开发启动、测试、构建、媒体资源和发布自动化。 |
| `scripts/release/` | Inno 安装器、文件清单、增量包、校验和、ECS 发布和版本保留策略。 |
| `assets/` | 应用图标、Inno Setup 脚本和随安装器使用的静态资源。 |
| `resources/` | 随应用发布的媒体二进制、许可证和锁定清单。 |
| `release/baselines/` | 紧凑的历史安装包文件清单；用于构建旧版本到最新版的直达增量包。保留它，不要和 `out/` 一同清空。 |
| `artifacts/` | 可复现的媒体包等受控构建输入；是否跟踪以 `.gitignore` 的例外规则为准。 |

发布入口为 `npm run release:local`，ECS 发布入口为
`npm run release:publish-ecs`。服务器保留策略与本地基线数量由发布脚本管理；
完整安装包和增量 ZIP 都属于发布产物，不属于源码。

## 测试与文档

| 路径 | 职责 |
| --- | --- |
| `tests/unit/` | 纯函数、渲染辅助逻辑和发布策略单测。 |
| `tests/worker/` | SQLite、索引、监听、导入及恢复测试。 |
| `tests/e2e/` | 真实 Electron / Playwright 端到端场景。 |
| `docs/plans/` | 已实施功能的设计和决策记录。 |
| `docs/reference/` | 运维、自动更新、移植和开发参考文档。 |
| `README.md`、`PRODUCT.md` | 产品入口说明和产品范围。 |

新增功能应包含对应的测试；与发布机制有关的变更还应更新
`docs/reference/` 中的运维文档。

## 本地可清理目录

以下目录被 Git 忽略，不能视为产品源码：

| 路径 | 内容 | 整理原则 |
| --- | --- | --- |
| `node_modules/` | npm 依赖 | 可由 `npm ci` 重建。 |
| `.vite/`、`dist/` | 开发和编译缓存 | 停止开发服务器后可重建。 |
| `out/` | 打包应用、安装器、完整包与增量包 | 保留当前待测试安装包；旧产物按本地发行保留策略清理。 |
| `tmp/` | 性能基准资料库、临时预览和日志 | 不提交；大型基准运行结束后可删除或移至专用测试盘。 |
| `.super-dev-user-data/` | 开发版 Chromium 缓存、缩略图和本机设置 | 不提交；删除会重置开发版本机状态。 |
| `test-results/` | Playwright 失败现场 | 仅在排查失败时保留。 |

## 当前整理原则

1. 先把功能性改动、测试、发布脚本和文档分组，再提交；不要混入构建输出。
2. 不删除 `release/baselines/`，它是增量更新链的输入。
3. 删除大型 `tmp/` 或旧 `out/` 前，先确认没有正在运行的开发版、打包或基准任务。
4. 每次发布后仅保留必要的本地安装器、发布基线和近期调试证据；线上版本保留由 ECS 发布脚本负责。
