| 决策 | 结论 | 状态 |
| --- | --- | --- |

| 性能优先级 | 首屏资源页先显示；侧栏计数、精确总数、缩略图和后台 reconciliation 均不得阻塞前台浏览。 | 已验证 |

### 2.3 版本号决策

1. 曾发生从 `0.1.x` 直接跳至 `2.0.0`/`2.0.1` 的编号失误讨论；结论是不能通过再发布较小版本“回退”更新系统，因为语义版本比较会把它视为旧版本。
2. 更新系统始终只接受更高版本；`0.2.0` 仅作为讨论过的编号，不把它认定为当前主线的正式最新版本。
3. 当前源码、Git 标签、ECS 最新清单和 GitHub Release 的主线版本均为 **`v2.2.8`**。

## 3. 主要产品决策与实现演进

### 3.1 AI 分析、智能合集与素材查找

- 明确“AI 素材查找”只面向**已分析素材**：LLM 解析自然语言，应用将其转为标签、颜色、格式、媒体类别等受验证条件；不把用户原话或未经验证的 LLM 结论直接用于数据库查询。
- 加入未分析/已分析筛选、单文件重新分析、文件夹批量分析、跳过结果统计和重分析覆盖前确认。
- 临时智能合集可以保留或丢弃；查找成功后的结果页不再保留输入阶段的“例如：帮我找……”提示。
- 解决不支持 JSON 输出的兼容模型：尝试兼容解析并给出清晰错误提示，不伪造检索条件。
- 先后改进了 AI 搜索结果的透明分块布局、毛玻璃效果和查找条件可读性。

### 3.2 资源库、链接目录与删除一致性

- 外部删除文件后，索引自动移除该资源，拒绝以损坏缩略图/错误占位掩盖真实状态。
- 链接文件夹采用批量索引和批量移除；新增目录时，“链接进度完成”与媒体任务队列状态分开呈现，避免把 palette/extract 任务的排队误解为目录未连接。
- 修复手动刷新链接目录报错，以及新加入图片未被 watcher 及时识别的问题。
- 修复资源区中把图片拖入同一资源空间内的空文件夹时，前端误进入全屏“松开以导入”状态且无法退出的界面问题；不改变正常文件移动 workflow。
- 文件夹页面也采用首屏分页策略，不再等待全量扫描后才显示；精确总数在后台补全。

### 3.3 浏览性能与后台保活

- “所有资产”已具备的部分先显示能力扩展至普通目录、链接目录和文件夹作用域。
- 首屏浏览请求与侧栏计数/统计 hydration 分离；后者失败或变慢不阻塞资源区。
- 缓存范围受库变更序列控制，避免旧目录/筛选结果被错误复用。
- 托盘最小化期间累积的文件系统事件改为可取消、按库串行的异步 reconciliation；恢复窗口后优先响应交互请求，再在空闲阶段处理扫描。
- 为 Worker 请求增加慢请求和超时归因日志，记录请求名、请求 ID、耗时，不记录文件内容或凭据。
- 加载界面增加真实的**不定进度条**；浏览无法可靠计算总量时不伪造百分比，导入/索引等有总量的任务仍显示确定进度。

### 3.4 调色、缩略图与浏览细节

- 色彩筛选由少量色块扩展为调色盘；匹配图像的多个代表色而不只匹配单一主色。
- 调色以归一化、版本化的 palette 索引存储；既有素材采用受限批次迁移，避免启动时全量重算。
- 右侧颜色概览的色块按代表色及其权重显示，与调色盘筛选共享同一颜色提取/索引基础。
- 不支持图像预览的 ZIP、EXE、APK 等格式显示后缀缩略图；根据深色/浅色主题自动使用对应配色。

### 3.5 主题与个性化

- 主题从单纯调色扩展为：主题色、深浅模式、层级投影、右键菜单亚克力强度、应用背景。
- 应用背景支持用户图像和透明度，满足“二次元主题”诉求；默认壁纸已纳入发行资源，而非依赖用户本地绝对路径。
- 用户提供的狐狸下午茶插画被设为最新默认背景资源。
- 字体大小提供仅作用于 Super Lib 的 1–4 档位，不影响 Windows、浏览器或其他应用；界面标签最终按用户要求仅显示数字 `1 2 3 4`。

### 3.6 顶部栏、选择模型与文件夹创建

- 初始决策：选中文件夹时，新建文件夹默认为其子级；这是正确的数据规则。
- 为创建根目录引入“左侧新建目标切回根目录”的交互，而不是通过跳转“所有资产”等公共模块取消当前浏览。
- 之后根据实际使用修正顶部栏行为：
  - 拖拽整个标题栏移动窗口时，**不改变当前文件夹和视图**；
  - 单击标题栏不改变浏览状态；
  - **双击**标题栏的非交互区域仅将左侧新建目标切为根目录，当前视窗继续停留在用户正在看的子文件夹/图片中；
  - 搜索、菜单、前进后退、窗口控制按钮等交互区域不受影响。

## 4. 更新机制：决策、故障与最终约束

### 4.1 架构决策

- 更新检查使用 ECS 的 HTTPS `latest.json`/兼容发布文档；版本文件位于不可变的版本目录。
- 下载采用 SHA-256 校验、取消、断点续传、完整包回退；不接受清单中任意外部 URL。
- 只有**当前安装版本精确匹配**的 delta 才会被选用，否则回退完整包。
- 首次确定“增量包”后进一步改为旧版本直达最新版的 delta：并非只保留相邻版本包。
- 服务器策略：最新 **5 个完整发行目录**；最新版本清单中最多保留 **20 个旧版本直达最新版**的增量包。超过保留窗口的用户安全回退完整包。
- 生成 delta 依赖 `release/baselines/<version>.json` 文件清单，不能随着 `out/` 构建目录清理而删除。

### 4.2 更新器故障处理历程

| 问题 | 根因/表现 | 处理原则与结果 |
| --- | --- | --- |
| 更新仍显示旧版本 | 安装路径、更新包和版本元数据没有同一版本链路。 | 调整完整/增量包、安装器和 `latest.json` 的版本一致性校验。 |
| 下载体积仍数百 MB | 只能提供完整包或缺少当前版本对应增量。 | 构建并发布精确版本 delta，后续发展为保留窗口内的直达 delta。 |
| 点击“重启完成更新”后无自动重启 | 应用退出、临时安装器、Inno 启动顺序不可靠。 | 不再依赖静默自动拉起；采用独立前台更新器并显式启动。 |
| 临时 `relay.exe`/`SuperSetup.exe` 找不到 | 临时文件在交接前被清理或路径生命周期不稳定。 | 安装器交接文件放在稳定的更新缓存，启动前校验存在性，避免提前删除。 |
| Inno “Cannot make a visible window modal” | 静默安装场景中创建可见模态窗口的方式不合法。 | 独立、非模态的更新窗口只在静默流程呈现，正常交互安装仍保留原行为。 |
| 更新器白色边框/按钮焦点虚线 | 使用了原生窗体与默认 focus outline。 | 统一深色矩形玻璃表面，显式处理焦点样式，保留键盘可用性而不显示白色虚线。 |
| 更新完成却自动启动或无法启动 | 更新成功状态与启动动作耦合，且启动路径不稳定。 | 完成页显示真实 100% 进度，用户点击“启动 Super Lib”才启动；失败给出可从开始菜单打开的明确说明。 |

4. `v2.2.8` 已发布至：
   - ECS 自动更新源：应用内更新使用；
   - GitHub Release：<https://github.com/aimtowin/Super/releases/tag/v2.2.8>；
   - GitHub Windows 安装包：<https://github.com/aimtowin/Super/releases/download/v2.2.8/SuperSetup.exe>。

## 7. 未完成/后续应继续按此原则推进的事项

1. 智能合集可继续扩展为更明确的“LLM 解释检索计划 + 用户可审阅条件”模式，但不得绕开本地已分析索引。
2. 主题可继续扩展为可导入/导出的主题包（配色、背景、透明度、字体档位），并维持本地资源引用的安全边界。
3. 更新发布时继续维护 5 个完整包与最多 20 个直达 delta；每次新发行前后验证旧版本到最新版的选择、哈希、安装与显式启动路径。
4. 性能验证应保留真实大库、托盘长时间恢复和链接目录增量扫描三类回归场景，但临时测试素材不得进入仓库或长期占用本地磁盘。
